# BatchBoss combined release: owner-assisted preflight

All development changes are staged on the global branch. No live account mutation, test discount, charge or deployment is performed by this runbook.

1. Keep public registration, public checkout, international launch offers and all new Paddle checkout gates disabled. In a separate sandbox Firebase project, configure sandbox credentials and a disposable test account; test real checkout, webhook and database state. Never copy live secrets into the sandbox.
2. Confirm the owner-approved live catalog and product IDs. For recurring prices use the exact standard amounts and explicit plan keys (weekly, monthly, annual, finder, full_suite); marketplace is a separate one-off price. Use the required default payment link https://app.batchboss.co.za/pricing/. Configure the permanent notification destination only against the actual deployed webhook URL. Subscribe to the eleven event types in the preflight script. Keep this destination and its secret permanently. Store API key and webhook signing secret separately in Firebase Secret Manager; never commit or paste either in chat.
3. Copy the parameter shapes in functions/.env.paddle.example into the existing project-specific env file (preserve all Paystack settings). Fill in the public client token, price/product mapping, marketplace IDs and configured test UID. Leave PADDLE_PUBLIC_CHECKOUT_ENABLED and BATCHBOSS_GLOBAL_SIGNUP_ENABLED false. Use a fresh test Firebase Auth UID, not an existing SA customer. The administrator-only preparePaddlePilotWorkspace callable can create the regional workspace. Verify the test account's email before checkout.
4. Run the read-only preflight on a checked-out release branch, after compiling functions. The live Paddle API key needs read permissions for checkout domains, verification, checkout URL settings, products, prices, discounts and notification settings, in addition to the runtime permissions required by the integration. Supply the actual deployed webhook URL with PADDLE_EXPECTED_WEBHOOK_URL. In a trusted terminal use read -rs to supply temporary credentials to the script, or access Secret Manager securely. The script compares the signing secret without printing it. Never expose credentials in shell history or logs. It verifies only remote configuration, not actual delivery/deployment.
5. Verify the exact final CI commit, isolated Firestore rules, staging web assets and device QA. Confirm existing local Paystack plan/renewal settings remain intact and the release artifacts are compatible. Merge and deploy the combined release only after the relevant gates have passed. A deployment of disabled features is not approval to open public sales.
6. Owner confirms sandbox checkout and live deployment. Create only a private, expiring, single-use 100% test discount restricted to the chosen test price. Owner completes one live checkout, not the assistant. Verify actual transaction, notification delivery, Firestore bindings and access. Check upgrade without billing, end-of-period cancellation, immediate cancellation; archive only the private test discount after verified cancellation. Never delete permanent notifications, products, prices, customers, subscriptions or transactions. For the real checkout pilot, use one test account and no public signup. Keep legacy Paystack active.
7. Confirm monthly launch-period count and expiration before creating launch discounts, test renewal terms and taxes, and verify listing payments/allowance and supplier regional readiness. Turn on public switches only after owner accepts all release gates. Android non-ZAR remains disabled until native QA is complete; supplier subscriptions remain South Africa-only pending international supplier plans.
